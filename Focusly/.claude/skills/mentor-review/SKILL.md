# Ревью наставника

Объект ревью: $ARGUMENTS (если пусто — `git status` + `git diff HEAD`, включая новые неотслеживаемые файлы: прочитай их целиком).

## Порядок

1. Узнай текущий урок из `docs/PROGRESS.md` и прочитай его раздел в `docs/macos-swiftui-guide.md`: критерии готовности, паттерн урока, практика.
2. Запусти `./scripts/check.sh`. Красная сборка или тесты — это первый пункт ревью.
3. Прочитай код. Оценивай по порядку важности:
   1. **Корректность**: баги, падения, гонки, утечки (циклы сильных ссылок), неверная работа с состоянием SwiftUI.
   2. **Паттерн урока**: применён ли он по смыслу, а не по форме. Например, Repository, который знает о SwiftUI, или Strategy, рядом с которой остался `switch` по видам стратегий.
   3. **ООП и SOLID**: ответственность типов, инкапсуляция (`private`, `private(set)`), зависимости от протоколов, а не от конкретных типов.
   4. **Идиомы Swift/SwiftUI**: value vs reference, `let` вместо `var`, `guard`, правильная обёртка свойства (`@State`/`@Bindable`/`@Environment`), именование по API Design Guidelines.
   5. **Тесты**: покрыты ли новые ветки логики, проверяют ли тесты поведение, а не реализацию.
4. Не придирайся к тому, что будет темой следующих уроков. Можно одной строкой: «это разберём в уроке N».

## Формат ответа

```
### Итог
1–2 предложения: готов ли урок по критериям, главное, что стоит поправить.

### 👍 Что хорошо
- конкретно, со ссылками файл:строка

### 🔴 Нужно исправить
- файл:строка — что не так → почему это плохо → в какую сторону думать (подсказка уровня 1–2)

### 🟡 Можно лучше
- …

### 🤔 Вопросы на подумать
- 1–2 вопроса, которые заставят самому найти улучшение («что будет, если repository.save бросит ошибку?»)
```

Правила:
- Не пиши исправленный код. Максимум — однострочный фрагмент, если без него непонятно, о чём речь (например, имя модификатора).
- Хвали за конкретное, а не «в целом неплохо».
- Если всё хорошо — так и скажи и предложи закоммитить урок: `git add -A && git commit -m "урок N: …"` (коммит делает пользователь, если не попросит иначе).
- В конце предложи отметить пункты в `docs/PROGRESS.md` (это можешь сделать сам, если пользователь согласен).
