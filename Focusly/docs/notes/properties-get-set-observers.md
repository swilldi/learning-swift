# Свойства: get/set, willSet/didSet и как ограничить значение

Разбирали 2026-11-04 на уроке 2. Началось с вопроса «как сделать свойство, которое можно менять снаружи,
но которое не принимает значение меньше 1».

## Короткое резюме

| | Свои данные | Когда срабатывает | Для чего |
|---|---|---|---|
| `get`/`set` | нет | при каждом чтении и записи | значение — проекция других полей |
| `willSet` | есть | до записи | подготовиться: убрать или отписать старое |
| `didSet` | есть | после записи | исправить или отреагировать; `oldValue` под рукой |

Общая оговорка: в `init` своего типа наблюдатели не вызываются.

## Два вида свойств

| | Хранимое | Вычисляемое |
|---|---|---|
| Где лежит значение | в самом объекте | нигде, считается при каждом обращении |
| Чем управляется | наблюдатели `willSet` / `didSet` | `get` (обязательно), `set` (по желанию) |
| `let` | можно | нельзя, всегда `var` |
| `Codable` (автоматический) | попадает в JSON | не попадает |

У одного свойства есть **либо** наблюдатели, **либо** `get`/`set`. Совместить нельзя: у вычисляемого
свойства нет записи в хранилище, за которой можно было бы наблюдать. Нужна реакция на изменение —
пишите её прямо в `set`.

## Вычисляемое свойство: `get` и `set`

`get`/`set` — это и есть полная запись вычисляемого свойства, а не отдельная фича. Разница только
в том, можно ли ему присваивать.

**Только чтение** — один `get`, слово `get` можно опустить:

```swift
struct Rectangle {
    var width: Double
    var height: Double

    var area: Double { width * height }
    // то же самое: var area: Double { get { width * height } }
}
// rect.area = 10  — ошибка компиляции: сеттера нет
```

**Чтение и запись** — `get` + `set`. `set` получает пришедшее значение как `newValue`
и раскладывает его по настоящим полям:

```swift
struct Temperature {
    var celsius: Double

    var fahrenheit: Double {
        get { celsius * 9 / 5 + 32 }
        set { celsius = (newValue - 32) * 5 / 9 }
    }
}

var t = Temperature(celsius: 0)
t.fahrenheit = 212   // set записал celsius = 100
```

Зависимые значения лучше делать вычисляемыми, а не хранить и «обновлять» вручную: тогда они не могут
разойтись с данными.

## Наблюдатели: `willSet` и `didSet`

Работают только у **хранимых** свойств. Порядок при `x.value = new`:

```
willSet   →   запись в хранилище   →   didSet
(newValue)                             (oldValue)
```

```swift
struct Thermostat {
    var target = 20 {
        willSet { print("сейчас \(target), будет \(newValue)") }
        didSet  { print("было \(oldValue), стало \(target)") }
    }
}

var t = Thermostat()
t.target = 25
// сейчас 20, будет 25
// было 20, стало 25
```

| | `willSet` | `didSet` |
|---|---|---|
| Когда | до записи | после записи |
| Что доступно | `newValue` (будущее); само свойство ещё старое | `oldValue` (прошлое); само свойство уже новое |
| Можно ли изменить значение | **нет**: `newValue` — константа, а присваивание свойству внутри `willSet` перезапишется (компилятор предупредит) | да: присваивание внутри `didSet` и есть итоговое значение, повторно наблюдатель не вызывается |
| Для чего | подготовиться, пока старое ещё действует: отписаться от старого объекта, убрать старое | исправить (зажать в диапазон) или отреагировать (лог, сохранение, обновить что-то снаружи) |

«Запомнить, что было» удобнее в `didSet`: там старое значение уже есть готовым как `oldValue`.

## Как ограничить значение: три способа

Пример — громкость от 0 до 10.

**1. `get`/`set` поверх приватного поля**

```swift
struct Speaker {
    private var storedVolume = 5
    var volume: Int {
        get { storedVolume }
        set { storedVolume = min(10, max(0, newValue)) }
    }
}
```

**2. `didSet`**

```swift
struct Speaker {
    var volume = 5 {
        didSet { volume = min(10, max(0, volume)) }
    }
}
```

**3. `private(set)` + метод**

```swift
struct Speaker {
    private(set) var volume = 5
    mutating func setVolume(_ value: Int) { volume = min(10, max(0, value)) }
}
```

| | `get`/`set` | `didSet` | `private(set)` + метод |
|---|---|---|---|
| Сколько полей | два: публичное + приватное | одно | одно |
| Присваивать снаружи | да | да | нет, только через метод |
| Привязка к контролу (`$model.volume`) | да | да | нет |
| Некорректное значение | в хранилище не попадает | на мгновение записывается, потом исправляется | не попадает |
| `Codable` | в JSON ключ приватного поля (`storedVolume`), нужны `CodingKeys` | ключ `volume` | ключ `volume` |
| Защищает в `init` | если `init` пишет через `volume` | **нет**, наблюдатели в `init` молчат | нет, проверка в `init` отдельно |

## Подводные камни

- **В `init` своего типа наблюдатели не вызываются.** Проверку значения в `init` нужно делать отдельно.
- **Любое изменение — это присваивание.** `t.target += 1`, вызов `mutating`-метода, `&t.target` в
  `inout`-функцию — всё это вызывает оба наблюдателя (для `inout` — один раз, после выхода из функции).
- **Наблюдатели срабатывают, даже если значение не изменилось.** `t.target = 20` при текущих 20 всё
  равно вызовет оба. Если важно — сравнивайте с `oldValue`.
- **Вычисляемое свойство пересчитывается при каждом обращении.** Для дорогих вычислений это заметно.
- **Тихо «зажимать» значение — тоже решение.** Вызывающий код не узнает, что его 0 превратился в 1.
  Иногда честнее бросить ошибку или вернуть `Bool`.

## Где в курсе

- Урок 2: `progress` у задачи — вычисляемое свойство только для чтения; `estimate` (оценка ≥ 1) —
  кандидат на `didSet`.
- Урок 8: `Stepper` в форме редактирования привязывается к оценке — свойство должно быть изменяемым,
